# SugApp dashboard (SaaS UI)

A single-page, self-contained dashboard with two views — an **Organization** view
(aggregate Respect Index, teams, behavior balance) and a **My Mirror** view
(one person's own metrics, quotes, and coaching rewrites). It is **generated from
the scorer's SQLite database**, so it shows whatever the pipeline actually scored.

```
Slack / transcript → score.py --save → sugapp.db → build_ui.py → saas_dashboard.html
```

## Files

| File | Role |
|---|---|
| `template.html` | The UI (HTML/CSS/JS). Standalone it renders bundled sample data; the build step injects real data at the `/*__DATA__*/` token. |
| `build_ui.py` | Reads a `store.py` database, computes the org + per-person view-model (reusing `score.respect_index` and the `K_ANON` threshold), injects it, writes `saas_dashboard.html`. |
| `seed_demo.py` | Fills a demo DB with multi-week, multi-team runs **offline** (no API key) so the dashboard has something real to show. |
| `saas_dashboard.html` | The built page (open it in a browser). |

## Run it (no API key, no Slack)

```bash
cd prototype/ui
python seed_demo.py                          # writes demo.db
python build_ui.py --db demo.db -o saas_dashboard.html
open saas_dashboard.html                      # or just double-click it
```

## Point it at real scored data

Once you've run the scorer with `--save` (live or `--demo`), build from that DB:

```bash
# from prototype/
python score.py --save --demo sample_transcripts/standup.json   # or a live run
python ui/build_ui.py --db ../sugapp.db -o ui/saas_dashboard.html
```

## What it demonstrates about the product

- **Two audiences, one product.** Individuals see their own words first (My Mirror);
  leaders see aggregates only (Organization).
- **k-anonymity in the UI.** Teams under `K_ANON` (5) people are suppressed in the org
  view — the seeded *Design* team (3 people) shows this.
- **Behaviors, with evidence.** Every "moment" carries the exact quote and, for the
  rough ones, a more respectful rewrite — no black-box scores.

## Notes

- `demo.db` is generated by `seed_demo.py` and is git-ignored — regenerate it any time.
- Colors were validated for color-vision-deficiency safety (respectful teal vs.
  to-work-on clay) in both light and dark themes.
